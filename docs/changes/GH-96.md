# GH-96: parse_decompose_criteria reads stale field name after prompt-asset rename

## What shipped

Commit 27e1fa9 (PR #95) changed `commands/DECOMPOSE.md` and
`stage_specs/decompose_feat.md` so the decompose agent emits its criteria
under a `proposed_criteria` key, but `adw/orchestrator.py`'s
`parse_decompose_criteria` was left reading the old `acceptance_criteria`
key. It therefore always returned `None`, and `run_decompose` blocked every
ticket routed through decompose with "decompose succeeded but emitted no
acceptance_criteria" even when the agent produced well-formed criteria. This
fix renames the single dict-key lookup to match the actual emitted payload.

## Behavior & breaking changes

- `parse_decompose_criteria` (`adw/orchestrator.py:292`) now reads
  `obj.get("proposed_criteria")` instead of `obj.get("acceptance_criteria")`.
  Any decompose status block still emitting the old key will now parse as
  empty — there is no backward-compatible fallback, since the prompt assets
  and this parser must agree on one contract.
- `run_decompose`'s failure message (`adw/orchestrator.py:337`) changed from
  "decompose succeeded but emitted no acceptance_criteria" to "... no
  proposed_criteria" to name the field actually being checked.
- The unrelated `Story.acceptance_criteria` dataclass field (`adw/tickets.py`)
  was deliberately left untouched — it is a different concept (a ticket's own
  AC list), not the decompose stage's JSON status-block key.

## How it was verified

- "parse_decompose_criteria reads the `proposed_criteria` key" → code at
  `adw/orchestrator.py:292` reads `proposed_criteria`; confirmed by
  `tests/test_decompose.py::test_parse_extracts_criteria_keyed_proposed_criteria`.
- "success outcome + non-empty proposed_criteria returns the list instead of
  blocking" → `tests/test_decompose.py::test_run_decompose_success_returns_criteria`
  passes, asserting `criteria == ["a", "b"]` and `problem is None`.
- "A regression test asserts extraction from a proposed_criteria-keyed
  payload" → new test `test_parse_extracts_criteria_keyed_proposed_criteria`
  asserts `parse_decompose_criteria('{"proposed_criteria": ["x", "y"]}') ==
  ["x", "y"]`.
- "Full suite stays green" → `uv run pytest -q` reported 399 passed.

## Review notes

Minimal, single-key rename with no new abstractions. Backward compatibility
with the old `acceptance_criteria` key was intentionally not added since
there's no external contract to preserve — the prompt assets and this parser
changed atomically and should stay in lockstep; a compatibility fallback
would have silently masked this exact class of bug in the future.

## File map

- `adw/orchestrator.py` — `parse_decompose_criteria` now reads
  `proposed_criteria`; docstring and `run_decompose`'s failure message
  updated to match.
- `tests/test_decompose.py` — existing fixtures/assertions updated from
  `acceptance_criteria` to `proposed_criteria`; added
  `test_parse_extracts_criteria_keyed_proposed_criteria` regression test.
