# T11 — Put a version number in the state file

We are planning some storage changes over the next while and I don't want a
future upgrade to have to guess what shape an old state file is in. Please
stamp the state file with a schema version.

What I want:

- Whenever state is saved, the file carries a top-level `"version"` field
  holding an integer. Start at 2 — treat today's unversioned layout as
  version 1. From now on the state file must always declare its version,
  whatever number it grows to in the future.
- Files written before this change (no `"version"` field) must keep loading
  exactly as they do today; the next time state is saved they come out
  versioned.
- Loading and re-saving must not lose or alter any items, suppliers or
  orders.

Acceptance criteria:

- A brand new store saves with version 2.
- An old unversioned file loads cleanly, and after any state-changing
  command the rewritten file carries the version field.
- Every existing command and report behaves exactly as before.
