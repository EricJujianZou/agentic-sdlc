# T43 — Report cache

Our data has grown and the reports screen recomputes everything on every
refresh, even when nobody changed anything in between. Add a caching layer:

- New function `stockroom.cache.cached_report(store, kind, **kwargs)` for at
  least the kinds "stock", "low", "monthly" and "history", taking the same
  keyword arguments the matching report takes (`threshold=`, `month=`,
  `sku=`) and returning exactly what that report returns.
- While nothing has changed, calling again with the same kind and the same
  arguments must return the very same object (no recomputation). Different
  arguments are cached separately.
- ANY change to the data — stock movements, catalogue changes, supplier
  changes, order operations, price changes, imports, undo — must invalidate
  the cache so the next call returns freshly computed results.
- To drive this, give the store a public integer `revision` that increases
  with every mutating operation and is untouched by reads and reports. The
  cache decides hit/miss from (revision, kind, arguments).
- The CLI report commands should go through the cache too. Reports must
  still never write anything.
