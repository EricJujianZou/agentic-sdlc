# T32: Store all dates as real ISO dates

Our data file has dates in whatever shape someone happened to type: "2026-1-5"
sits next to "2026-01-05", and string comparisons keep biting us. Please clean
this up once and for all:

- Every date we store (order dates, arrival dates, price-change dates, shipment
  dates) must be a zero-padded ISO `YYYY-MM-DD` string.
- Old data files keep loading, but legacy dates are normalized on load: a stored
  "2026-1-5" comes back as "2026-01-05" everywhere (reports, exports, scripts)
  and is written back normalized on the next save.
- Anywhere a date is accepted (e.g. `place-order --date`), both `YYYY-MM-DD` and
  unpadded `YYYY-M-D` are fine and get normalized. Anything that is not a real
  calendar date is a user error: exit code 1 and no change to the data.
- Date filtering and comparison in reports must work on parsed dates, not on
  string prefixes.
- Bump the state file's version to 5. Files written in every earlier version
  must still load.
