# T41 — Read-only mode

We sometimes open the stockroom data from machines that must never change it
(the accounting laptop mounts the share read-only, and auditors work on a
copy). Two things, please:

1. A global `--read-only` flag: `stockroom --data DIR --read-only <command>`.
   With it, any command that would change our data must refuse with exit
   code 1 and an error message mentioning read-only mode, and must not touch
   any file in the data directory at all — not even a rewrite of identical
   content. Reports, search and CSV export must keep working normally.
2. A persistent switch: `stockroom --data DIR lock` marks the data itself
   read-only (the flag is stored with the data, so it survives across
   invocations and machines); after that every mutating command refuses just
   like above, even without `--read-only`. `unlock` clears the flag, and
   `unlock` must always be allowed — otherwise we could never recover.

Acceptance: locked or flagged, every mutating command (add-item,
add-supplier, receive, ship, transfer, place-order, receive-order,
cancel-order, ship-order, set-price, import-csv, undo, restore, ...) exits 1
and leaves every byte in the data directory unchanged; read-only commands
still succeed.
