# T40: Keep the event log in its own file

Since the audit trail landed, our state file has ballooned — most of it is
events now, and every backup copies the lot. Split it out:

- Events live in a sidecar file next to the state file: same name with the
  `.json` suffix replaced by `.events.json` (so `state.json` gets a
  `state.events.json`). The sidecar holds a JSON object `{"events": [...]}`.
- Loading is transparent: `store.events` works exactly as before. A state file
  with no sidecar simply has no events yet.
- Old state files with embedded events still load fine; on the next save the
  events move to the sidecar and the main file stops embedding them.
- Bump the state file's version to 6. Files written in every earlier version
  must still load.
