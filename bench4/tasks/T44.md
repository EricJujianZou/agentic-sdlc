# T44 — Split the storage per warehouse (and stop corrupting on crash)

Two operational problems with our data file:

- `state.json` has grown huge; every save rewrites all of it, and two people
  syncing the share constantly conflict on that one file.
- A power cut mid-save once left us with a truncated, unreadable file.

Please restructure how the data directory is stored:

- `state.json` stays, but becomes a small "meta" file: it must carry
  `"version": 7`, the suppliers, the item catalogue (everything about an
  item except its per-warehouse quantities) and the settings/counters we
  keep today.
- Per-warehouse quantities move to one file per warehouse,
  `items.<warehouse>.json` — a plain JSON object mapping SKU to integer qty.
- Orders move to `orders.json` (the JSON list of order records).
- The activity/event history stays in its sidecar file as today.
- Every file write must be atomic: write to a temporary file first, then
  rename it into place. Never leave `*.tmp` litter behind.
- Loading must still accept every format we have ever written, all the way
  back to the original single-file layout, and the first save after loading
  an old file upgrades it in place to the new layout.
- Nothing about the Python API or the CLI changes.
