# T23: Keep money as whole cents

After the valuation episode we no longer trust fractional dollar amounts
inside the system. We want money held as whole cents everywhere, so nothing
can ever drift again — without changing how we use the library or the CLI:

- The state file moves to `"version": 4`. On disk, item prices are stored as
  an integer field `unit_price_cents` (replacing the fractional
  `unit_price`), and price-history entries store integers `old_cents` /
  `new_cents` (replacing fractional `old` / `new`). Everything else keeps
  the version-3 layout.
- All internal money arithmetic — line values, totals, anywhere dollar
  amounts get multiplied or summed — happens in exact whole cents.
- The public surface must not change: `Item(unit_price=3.5)` still works and
  `item.unit_price` still reads back as 3.5; `price_history` entries still
  expose `old`/`new` as dollar amounts; reports still return dollar figures;
  the CLI still takes prices as decimal dollars.
- Old files keep loading: the original unversioned layout, version 2 and
  version 3 all load correctly, and get written back as version 4 on the
  next save.
