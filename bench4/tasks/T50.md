# T50 — One stable `stockroom.api` module

We are embedding stockroom into our ERP. Today our integration imports from
five different modules and breaks somewhere every time you refactor. Give us
ONE module — `stockroom.api` — that exposes every capability the tool has
grown, with the names and signatures below, and keep it stable. The old
module paths (`stockroom.store`, `stockroom.reports`, `stockroom.csv_io`,
`stockroom.cli`, ...) must keep working for our existing scripts.

Conventions: user errors raise `ValueError`; every mutating api function
persists its change to disk immediately; `store` below is the object
returned by `open_store`.

## Store / session
- `open_store(data_dir) -> store` — loads `<data_dir>/state.json` in ANY
  format we have ever written (the original single-file layout through the
  current split layout); an empty store when nothing is there yet.
- `save(store)` — persist in the current layout (atomic writes).
- `store.revision` — public integer, goes up with every mutation.
- `set_read_only(store, flag)` — the persistent read-only switch; while
  set, every mutating api function raises `ValueError`. Calling
  `set_read_only` itself is always allowed.
- `backup(store) -> path`, `restore(store, path)`, `list_backups(store)`.

## Catalogue
- `add_supplier(store, supplier_id, name, email, lead_time_days=0)`
- `add_item(store, sku, name, qty=0, price=0.0, supplier=None,
  category=None, warehouse="main")` — SKU identity is case-insensitive
  (stored canonically), category defaults to "uncategorized".
- `set_price(store, sku, price, date)` and `price_history(store, sku)`.
- `search_items(store, query)` — case-insensitive substring match on name
  and SKU, returns the matching items.

## Stock
- `receive(store, sku, qty, warehouse="main", actor=None)`
- `ship(store, sku, qty, warehouse="main", actor=None)` — never below zero
  (raises, nothing changes).
- `transfer(store, sku, qty, source, dest, actor=None)` — same overdraw
  protection; a new destination warehouse is fine.

## Orders
- `place_order(store, sku, qty, date, supplier=None, actor=None) -> order`
  — dates in any of our historic spellings are accepted and normalized;
  the supplier is inferred from the item when unambiguous.
- `receive_order(store, order_id)`, `cancel_order(store, order_id)` — the
  status rules apply (only pending orders may be received or cancelled;
  anything else raises).
- `ship_order(store, order_id, qty)` — partial receipt tracking.
- `scheduled_reorders(store, as_of)` — auto-place reorders, idempotent per
  day and SKU.

## Money
- `format_money(amount) -> "$X.XX"`.
- `set_discount(store, category, percent)` and `discounts(store)`.
- `set_tax_rate(store, percent)`.
- `order_total(store, order_id)` — qty x price, minus the item category's
  discount, plus tax; exact to the cent.
- `invoice_text(store, order_id) -> str`.

## Reports (read-only, cent-exact money, date-aware)
- `stock_report(store) -> {"rows": [...], "total_value": ...}` — rows carry
  at least sku, name, qty, unit_price, value.
- `low_stock(store, threshold=5)` — list of rows (sku, name, qty), items at
  or below the threshold.
- `low_stock_by_category(store, threshold=5)` — dict category -> rows.
- `reorder_suggestions(store, threshold=5)` — rows carry sku, supplier_id,
  qty, suggested_qty where suggested_qty accounts for already-pending
  orders; agrees with `low_stock` about items exactly at the threshold.
- `monthly_orders(store, month)` — includes orders however their date was
  originally spelled; `order_history(store, sku)` — chronological, rows
  carry at least id, qty, date, status.
- `per_warehouse_report(store)`, `turnover(store)`,
  `monthly_revenue(store, month)`, `supplier_on_time(store)`,
  `order_aging(store, as_of)`, `weekly_shipments(store)`.
- `summary(store) -> dict` with keys "valuation" ("$X.XX" string),
  "low_stock" (list of SKUs), "pending_orders" (int), "top_category"
  (str or None), "events" (int).
- `cached_report(store, kind, **kwargs)` — the same caching contract as
  the report cache (same-object on hit, invalidated by any mutation).

## CSV / exchange
- `export_items_csv(store, path)` / `import_items_csv(store, path)` —
  import accepts every header version we have used (missing category means
  "uncategorized", money cells like "3.5" and "$3.50" both parse, SKUs that
  differ only by case are the same item); export includes the category
  column.
- `export_events_csv(store, path, op=None, since=None)`.
- `export_archive(store, path)` / `import_archive(path, data_dir) -> store`
  — the single-file snapshot, activity history included.

## Activity / undo
- `events(store)` — the activity history as a list of dicts (at least op,
  args, actor per entry); every mutating api call adds at least one entry.
- `undo(store, steps=1)` / `redo(store, steps=1)` — same behavior as the
  CLI commands, applied to `store` and persisted.

## Operations
- `batch_apply(store, csv_path, dry_run=False)` — the all-or-nothing batch.
- `fsck(store)` — list of problem strings, empty when the data is clean.
