# T07 — Order lifecycle sanity

Last week somebody received order 7 twice and our stock counts were
wrong for days. Someone else managed to cancel an order that had already
been received. Please make the order lifecycle strict.

An order starts `pending`, and the only allowed moves are
pending -> received and pending -> cancelled.

- Receiving or cancelling an order that is not pending must fail: the
  CLI exits 1 with an error message, and `Store.receive_order` /
  `Store.cancel_order` raise `ValueError`.
- A refused transition changes nothing — in particular, stock must NOT
  be added a second time when an already-received order is "received"
  again, and a cancelled order must stay cancelled.
- Normal receiving and cancelling of pending orders keeps working.
