# T10 — Undo

**Motivation:** Fat-fingered an entry? Users need to step back safely.

**Required behavior:**

1. `Ledger.undo(self, n: int = 1) -> int` reverts the last `n` mutating
   operations and returns how many were actually undone (0 if there is no
   history; never more than the recorded history).
2. Mutating operations recorded in history:
   - `add` (undo removes that entry),
   - `remove` (undo restores the removed entry),
   - `add_recurring` (ONE history item — undo removes all entries it created),
   - `set_budget` (undo restores the previous limit, or removes the budget key
     entirely if the category had none before).
3. Non-mutating calls (`entries`, `total`, `query`, ...) must not affect the
   history.
4. Undo applies strictly in reverse chronological order of operations.

**Verified by:** `bench/target/tests/test_t10.py`
