# T03 — Fix the date-handling bug

**Motivation (bug report):** A user added an entry with date `2026-1-5` via the
library. `report.month_total(ledger, 2026, 1)` does not include it, and mixed
ledgers list entries in a strange order. Money silently disappears from
monthly reports. Somewhere the code assumes a specific date string shape.

**Required behavior:**

1. Find and fix the root cause. Dates like `2026-1-5` and `2026-01-05` must
   behave identically everywhere (monthly totals, monthly summaries, sorting,
   storage round-trips).
2. The fix must normalize dates to zero-padded ISO form `YYYY-MM-DD` at
   `Entry` creation time, so `Entry("2026-1-5", ...).date == "2026-01-05"`.
   Already-padded dates pass through unchanged.
3. Entries loaded from JSON files get the same normalization.
4. Do not change the public signatures of `Entry`, `month_total`, or
   `monthly_summary`.

**Verified by:** `bench/target/tests/test_t03.py`
