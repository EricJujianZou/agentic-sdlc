# T08 — Exact money (integer cents)

**Motivation:** Float summation drifts (`0.10 + 0.20 != 0.30`). Money must be
exact.

**Required behavior:**

1. `Entry` stores money internally as integer cents. Public surface:
   - Constructor keeps accepting a float `amount` (converted with
     `round(amount * 100)`).
   - `entry.amount_cents` -> `int`.
   - `entry.amount` still yields the float value (`amount_cents / 100`) so all
     earlier code and tests keep working.
   - Classmethod `Entry.from_cents(date, cents: int, category="uncategorized",
     note="") -> Entry`.
2. `Ledger.total_cents(self) -> int`; `Ledger.total()` and
   `Ledger.totals_by_category()` must be computed from cents so results are
   exact floats (e.g. ten entries of 0.10 total exactly 1.00).
3. `report` functions keep their float return types but must also be
   cents-exact internally.
4. Storage: saved JSON entries gain `"amount_cents"` (int) alongside the
   legacy `"amount"` float; `load` prefers `"amount_cents"` when present and
   falls back to `"amount"` for old files.

**Verified by:** `bench/target/tests/test_t08.py`
