# T06 — Multiple named ledgers per file

**Motivation:** Users want separate "personal" and "work" ledgers without
juggling multiple files.

**Required behavior:**

1. `storage.save(ledger, path, name: str | None = None)` and
   `storage.load(path, name: str | None = None)`.
2. With `name=None`, both behave exactly as before (legacy single-ledger JSON
   format). Full backward compatibility is required.
3. With a name, the file uses a multi-ledger format: a top-level object with a
   `"ledgers"` key mapping ledger names to single-ledger objects. Saving a
   named ledger into an existing multi-ledger file must preserve the other
   named ledgers in it.
4. `storage.load(path, name=...)` returns the named ledger. As a compatibility
   bridge, loading a LEGACY-format file with `name="default"` returns the
   legacy ledger.
5. CLI: a top-level `--ledger NAME` option; when given, all subcommands read
   and write the named ledger in the multi-ledger file at `--file`. Without
   it, the CLI keeps its legacy behavior.

**Verified by:** `bench/target/tests/test_t06.py`
