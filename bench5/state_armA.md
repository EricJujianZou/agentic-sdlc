# Arm A carried state (60-line cap)
## Harness traps (read first)
- NEVER type `cd` in a FOREGROUND Bash call — not `cd X && cmd`, not `cd X; cmd`, not a second `cd` later in the SAME compound line. That call usually
  SUCCEEDS; the NEXT one dies, so it feels unrelated (r022 and r025 each did it twice, having read this line). cwd PERSISTS and the PreToolUse hook is the
  *relative* `hooks/pretooluse_guard.py`. FIX: `Write` a .sh that `cd`s inside, `git -C <dir>`, or — for a repo-local node tool — `npx --prefix <repo> <tool> <ABS path>`. DISARM IT UP FRONT — right after cloning, `ln -sfn
  <repo>/hooks bench5/workspaces/task/hooks`; a stray `cd` then costs nothing. DON'T `rm` that symlink in your deliver script (r028 did, and the next
  Bash call died) — it is untracked, so `git diff` never sees it; just leave it. Already stuck? load `Monitor` (unhooked), re-make the symlink there.
- The guard denies force-deletes if the command holds ANY absolute/`..` token (use `rm -f … && rmdir`), and bare `sleep N && cmd`; it scans the LITERAL text, so a heredoc merely QUOTING one is denied — use Write (r023 lost a whole compound call, python edit included, to an `rm -rf` inside a heredoc). Long installs blow the 120s timeout: background them, ending `echo exit=$? >>log`; block via `until grep -q '^exit=' log; do sleep 5; done`.
- Multi-point edits: `Write` a .py of `assert s.count(old)==1; s=s.replace(old,new)` and run it — beats N Edit calls, the asserts catch a stale assumption instantly, and a revert-and-rerun NEGATIVE CONTROL is two more runs of it. NOT `python3 -c "..."`: inside double quotes `'\''` is NOT an escape, so one apostrophe in the payload (a Go comment's "doesn't") makes the pattern silently unmatchable (r024).
  CHECK LINE ENDINGS FIRST (`b'\r\n' in open(f,'rb').read()`) — a Linux clone of a CRLF-authored repo is LF on disk, and the wrong ending fails every
  assert. Same trick for mechanical test sweeps, and for slicing out a whole func by index("start")..index("next decl").
## Protocol mechanics
- Deliverable is `git -C bench5/workspaces/task diff` = worktree-vs-index, so ANYTHING STAGED IS INVISIBLE: a new file needs `git add -N <path>`;
  `git rm` HIDES a deletion (use plain `rm`); check `grep -c '^new file mode'`. `git stash push -u -- src` then REFUSES ("Entry … not uptodate"):
  `git restore --staged <newfile>`, stash / run / pop, re-`add -N` — script that dance; a FAILED stash silently runs your CHANGED tree as "baseline".
  A `.ts`->`.tsx` rename = plain `rm` old + write new + `add -N`. Finish by stashing src and `git apply --check <patch.diff>` — proof it applies.
- Package managers REWRITE LOCKFILES and install hacks live in package.json: `git status --short` before diffing, then `git checkout -- <lockfile> package.json`; build scratch venvs / vendored deps OUTSIDE `workspaces/task` (`workspaces/vendor/` is gitignored too). Any repair you make INSIDE tracked dirs (vendor/, submodules) must be listed in that same restore step, and `git checkout --` does NOT remove files the repair ADDED — `git clean -fd <dir>` too.
- Clone shallow+partial into the gitignored `bench5/workspaces/task`: `git init`; `git remote add origin <url>`; `git fetch --depth 1 --filter=blob:none origin <sha>`; `git checkout FETCH_HEAD`. Never fetch the fix commit. Submodules aren't fetched — `git ls-tree HEAD <path>` gives the pinned SHA, and cloning one at EXACTLY that SHA leaves the parent diff clean (r025: lib/web's whole suite is red until `webassets/` exists).
- The Requirements list IS the scope contract: one edit each, re-walk it against the diff; the LIST beats a vaguer blurb, its SILENCE on a nearby thing means leave that alone — even when your change strands it (r031's global `-wp-ignore-inactive` flag lost its only reader once the setting moved per-server; no bullet said remove it, so it stayed, declared in meta). Its FILE PATHS can be WRONG (r019 said `executor/worker.py`, real `executor/process/worker.py`) — locate by symbol. "Interface" is LLM-written, maybe uncompilable: honour its name/default/behaviour, and its PARAM ORDER — it is derived from the real patch.
  Bullets CONTRADICT each other (r026: "port must never be modified" vs "the segment structure must cover host, port, path, …"). Tie-break toward the behaviour an EXISTING test pins; obey a bullet that only contradicts the BASE CODE (a changed default) — that is the patch talking. Record the call. A TITLE that sounds sweeping ("X should ALWAYS move with Y") over a bullet naming ONE trigger site (r030: only the drop-on-INBOX branch of three) = build the named site; the odd specificity is the real patch showing through, and the other branches often have unspecified side-effects (section flips) you would have to invent.
- "Centralize X in <one file>; ALL UI calls it" means EVERY inline copy, not just the file the next bullet names — grep the old body's distinctive call and convert each; dropping the now-dead param then trips react-hooks/exhaustive-deps, so lint the touched files after. A bullet asking for "a centralized helper rather than ad-hoc dialog creation" wants a pure EXTRACTION of the existing inline block into one local fn both call sites use — move it verbatim, don't redesign (r028).
- DEGENERATE lists exist (r020: six bullets restating "export this one function") — a FLOOR: build what the problem statement needs, never invent UI from another repo's markup. Prose PARAPHRASES behaviour that often ALREADY EXISTS — CHECK THE BASE: r022's "Store must implement all storage.Store methods" was already true via one embedded field; r025's "authenticate with any registered device" was already true server-side, only GENERATION was single-device; r031's whole Status=="inactive"/"active" bullet was already the base code, so that bullet cost one test, not one edit.
- PLUMB/UNPLUMB-A-PARAM: put it beside its sibling at EVERY hop incl. React props, then let tsc/pyflakes enumerate the call sites (they find test files grep misses) — a REMOVAL also orphans imports, so stash and re-lint to separate PRE-EXISTING hits. And a new injected dep leaves the OLD one DEAD: hidden tests construct facades POSITIONALLY, so REPLACE the dead ctor param in place (r023: `worker: WorkerImpl` -> `operationProgressTracker`), never append a 9th arg and leave an unused 5th — an arg-shift silently breaks every hidden test.
- DELETING a cross-cutting middleware/feature orphans more than imports: its private helper types+funcs, its test cases, AND the spies in the package's support_test. The compiler flags only unused imports and locals, so grep every symbol the deleted body touched and drop the ones only it used.
- When the Interface demands a REFACTOR, EXISTING tests pinning the old signature WILL fail: that is the change, not a bug — update them, PROVE it (stash source only), say so. Read them BEFORE coding: asserts are free spec. A WIDENING change (one value -> a list) is the opposite: keep the old field so untouched tests still pass, and that free pass IS your backward-compat evidence. Replacing a boolean with the richer value it was derived from (`isPrivate` -> `joinRule`) must keep the OLD default: pick the fallback that reproduces the base truth table, and test the no-state case.
## Repo families
- Go: pre-2021 repos ship an INCOMPLETE go.sum — `go mod download <mod> <mod>` with the modules NAMED (argless adds nothing, tidy churns); keep and declare those. Cold `go build ./...` = minutes of downloads (background it); `-tags <x>` may be RED AT BASE; `gofmt -l` flags BASE-unformatted files (go1.19 comment reflow hits most 2021 repos — read `gofmt -d` and confirm no hunk is yours), so format only YOURS; lint = Makefile + .golangci.yml; `go vet ./<pkg>/...` type-checks _test.go too and also reports PRE-EXISTING findings (r025: "call to time.Since is not deferred") — the real gate when a package's own suite is integration-only (teleport tool/tsh).
  A repo's OWN build tag can be RED AT BASE for a reason that is not your problem (vuls: `-tags=scanner ./...` dies because untagged cmd/vuls/main.go registers `!scanner` cmds) — prove it at base, then build/vet only the TOUCHED pkgs under that tag. vuls itself (2021, go.mod go1.15) is fully green on go1.24: `go build ./...` + `go test ./...` ~4 min cold, 0 fails; only `gofmt -s -l` flags base files (go1.19 comment reflow + missing `//go:build`).
  A BUILD-TAGGED PLATFORM file (darwin cgo + .m/.h) CANNOT be compiled on linux: gofmt proves it parses, then mirror the sibling func exactly; one new native method touches the .h decl, the .m body, the tagged Go impl, the `!tag` noop impl, AND the test fake (which must satisfy the interface). Embedding: a field typed as an ALIAS keeps the ALIAS name (`type A = B; struct{ *A }` -> field `A`), so an Interface spec naming such a field compiles as written; a non-nil embedded POINTER also flattens its JSON.
- Go, VENDORED 2021-era repo (teleport): vendored `modern-go/reflect2 v1.0.1` SEGFAULTs on go1.24 swiss maps, so the ENTIRE suite panics at base in `UnsafeMapIterator.HasNext` and reads like your bug. go.dev is 403 through the proxy but proxy.golang.org is ALLOWED: `curl proxy.golang.org/github.com/modern-go/reflect2/@v/v1.0.2.zip`, DELETE `vendor/.../reflect2/*.go *.s` first (leftovers redeclare `resolveTypeOff`), copy v1.0.2 in; restore vendor/ in the deliver script.
- Go with a `go.work` (flipt): GOFLAGS=-mod=mod is REJECTED in workspace mode (drop it); every build/test run dirties `go.work.sum`, so `git checkout -- go.work.sum` right before diffing. `_tools/go.mod` pins an ancient golangci-lint that won't run on a modern toolchain — practical gate is `gofmt -l <touched>` + `go vet ./<pkg>/...`. Packages needing live redis/network (internal/cache/redis, gitfs) are RED AT BASE — prove it by stashing source and re-running just those, not the whole suite. `./rpc/...` from the root "matched no packages" (separate module) but the FULL path `./rpc/flipt/<pkg>/...` works — don't read the warning as "nothing to test".
- NEVER hand-edit a generated `.pb.go` (rawDesc is serialized bytes) — REGENERATE, and NEGATIVE-CONTROL the generator first: regenerate from the UNCHANGED .proto and diff vs the committed file; byte-identical proves your plugin version matches (versions are in `_tools/go.mod` + the file's own header). buf.build is 403 through the proxy, so `buf generate` at repo root dies ("server hosted at that remote is unavailable") resolving buf.lock BSR deps — if your proto only imports well-known types, copy it alone into a scratch dir under the SAME relative path with a deps-free `buf.yaml` + a one-plugin `buf.gen.yaml`, generate there, copy the result back. A field ADD touches only `<x>.pb.go`; gw/grpc/sdk generated files are service-level and stay untouched.
- Python (ansible/qutebrowser/openlibrary): scratch venv, never edit requirements.txt. Modern pytest on an old repo = a FIXED set of unrelated failures
  + collection ERRORS (`parametrize` names-vs-values) — `--ignore` that dir, compare FAILED sets, don't chase green. ansible units: run SERIALLY (xdist
  INTERNALERRORs) with `PYTHONPATH=<repo>/lib:<repo>/test`, ignore `test/units/module_utils/basic` + `config/manager`, install `pywinrm pypsrp` or suites
  SKIP; gates = `pycodestyle --max-line-length=160 --ignore=E402,W503,W504,E741,E203` + pyflakes; a new module option = argument_spec + its OWN DOCS block.
  A 2019 PyQt5 repo (qutebrowser) is NOT hopeless — its own suite runs 100% green on py3.11 with `PyQt5==5.15.11` + `pytest==7.4.4` (pytest 8 DROPS the
  `pytest_ignore_collect(path)` hook its conftest defines and `--strict`; 4.x won't install). Also: `pip install pytest-xvfb` or conftest's
  `getoption('--no-xvfb')` errors EVERY fixture; `QT_QPA_PLATFORM=offscreen`; and override the ini — `-o addopts="" -o filterwarnings=` — since
  `--faulthandler-timeout`/`--instafail` are gone and `filterwarnings=error` turns a pkg_resources DeprecationWarning into a conftest ImportError.
  Importing `qutebrowser.utils.<x>` in a scratch repro dies on a circular import: `import qutebrowser.utils.jinja` FIRST, then everything works.
- yarn/jest webapps: a blocked dep host dies with a BARE `ECONNRESET` or 403 — name it via `curl -sS "$HTTPS_PROXY/__agentproxy/status"` -> `recentRelayFailures`. element-web / matrix-react-sdk (yarn 1; a 2023 element-hq/element-web base commit clones as `"name": "matrix-react-sdk"` — same repo, pre-merge history) needs THREE fixes, then `yarn install` takes ~70s: `CYPRESS_INSTALL_BINARY=0`; git-clone `matrix-js-sdk` at yarn.lock's SHA into `workspaces/vendor/jsdk` + point package.json at `file:../vendor/jsdk` (codeload 403); `@matrix-org/olm` -> plain `3.2.15` off npm (gitlab.matrix.org 403).   Gates: `npx tsc --noEmit --jsx react` (the vendored jsdk leaves ~11 PRE-EXISTING node_modules TS7016 errors — diff the error SETS, don't chase), `npx jest --ci -w 4` (~5 min, 479 suites, StopGapWidget's 3 failures are base), eslint + `prettier --check`; a new data-testid churns .snap in UNRELATED suites (`npx jest -u`). protonmail/webclients: `node .yarn/releases/yarn-<v>.cjs install --mode=skip-build` (rewrites ~900 lock lines — restore; `mv node_modules/canvas node_modules/canvas__off` or components suites die); gates = `npx tsc -p applications/<app>/tsconfig.json --noEmit`, jest from the app dir, eslint --fix + prettier (120). Install is ~2.5 min and exits 0; the canvas hack is only needed for packages/components, applications/mail is clean. mail's jest ini forces COVERAGE ON — pass `--coverage=false` or 100+ lines of table bury the result; a 2-file focused run is ~100s, MailSidebar.test.tsx ~12 tests. Base files there ARE prettier-clean, so a `[warn]` on your file is YOURS — stash-and-recheck to be sure, then `prettier --write` it.
- npm-workspace TS monorepo (tutanota): `npm ci --ignore-scripts` installs clean and leaves package-lock.json untouched, but you MUST then `npm run build-packages` (tsc -b of packages/*) or `npx tsc --noEmit` drowns in ~4.5k phantom "Cannot find module @tutao/*". `cd test && node test` is RED AT BASE on node 22 (2022 better-sqlite3/keytar fail node-gyp) — use the mini-suite recipe below. Working gates: tsc for src and `-p test`, `npx prettier -c <files>` (some base files are ALREADY unformatted — confirm by stashing), `npx eslint <files>`.
- NodeBB: NO root package.json (it is generated from `install/package.json`, where the pinned tool versions live) and no node_modules; its mocha suite needs a live mongo/redis, so don't try — stub-load the one module instead. `src/promisify.js` re-wraps every exported async fn — declare `async` (it tests `constructor.name`); knobs go via `plugins.hooks.fire`. ## Verification habits
- NO DATABASE? Don't skip verification — stub it. Load the module under test directly and intercept its deps by overriding `Module.prototype.require`, gated on `this.filename === <file>` so only that file sees stubs (py: `sys.modules[...]=Mock()`; go: the repo's own `common.StoreMock` + a cacheSpy).
- TEST HARNESS RED AT BASE (native deps, browser-only bundler plugins, a vendored lib too old for the toolchain, an unfetched submodule)? Don't give up and don't assume it's yours — REPRODUCE AT BASE FIRST (stash source, re-run), then REPAIR THE ENVIRONMENT (r025: swap one vendored dep, clone one submodule — ~15 min bought two whole suites) or REBUILD A MINI SUITE (r023, ~20 min): copy the repo's bootstrap file, import the N test files you care about + the runner's `o.run/report`, and re-run the repo's OWN esbuild/webpack config MINUS the offending plugins (`define` their globals to dummies). Keep it in the scratchpad so the diff stays clean.
- Baseline FIRST when a suite DOES run: whole suite at base into fails_before.txt, again after, `comm` the sorted FAILED/ERROR sets; only the DELTA
  counts (r019: 253 fails both sides, 0 new, 2 fixed). A red test that PASSES when re-run ALONE is flakiness, not your regression, and one that fails only
  in the BEFORE run is usually a TIMING test, not something you fixed (r025 PasswordSuite.TestTiming). STASH SOURCE ONLY: lockfiles/vendor unbuild the
  base. Same for tsc/lint — the repo's PINNED linter, run FROM THE REPO ROOT so nested configs apply, before/after sets diffed.
- A SIGNATURE REFACTOR can't be negative-controlled by stashing (your new tests won't COMPILE at base). Instead keep the new signature and revert the ONE
  semantic line (r031: `cnf.IgnoreInactive` -> the old global `c.Conf.X`), re-run, confirm exactly the behaviour tests flip red, restore. Also: a function that
  looks like it needs the whole app wired up is often offline-testable — package loggers are usually `init()`ed to a discard writer, and PREFILLING the cache/dep
  map it consults makes every network branch unreachable, so you can assert real end-to-end counts with no server.
- Write a THROWAWAY test file inside the repo's OWN test tree (untracked -> invisible to `git diff`; `rm` it before delivering) with one case per Requirements bullet, then NEGATIVE-CONTROL the whole file by stashing src and re-running: the bullets you implemented must go red, the pre-existing behaviour you preserved must stay green. That split is the cheapest proof the diff is both live and scoped (r028: 6 of 11 flipped).
- DON'T COPY A FIXTURE FROM THE REPO'S OWN TESTS WITHOUT CHECKING IT REACHES YOUR BRANCH — matrix-react-sdk's helper writes `m.room.create` `content: {version}` but `Room.getVersion()` reads `room_version` and falls back to "1", so every existing "v8 room" test is really a v1 room and the version gate is never exercised. Assert the precondition too (e.g. that the upgrade pill is ABSENT on a SUPPORTED version), or a green test proves nothing.
- NEVER hand-edit a GENERATED file (element-web `src/i18n/strings/en_EN.json`): run its generator (`npx matrix-gen-i18n`) and diff — it re-orders by source traversal (a new file shifts strings, and a string you REUSE moves to its new first-seen site) and re-adds "orphans" another component still uses. PURE-EXTRACTION / MOVE refactors get a free oracle: every existing test that passes UNTOUCHED proves behaviour is unchanged — still cover the NEW seam with real cases, then read the diff hunk by hunk.
- RETARGETING A REDIRECT (or any handoff) — read the TARGET's own controller for its PRECONDITION first: NodeBB's `/register/complete` bounces to `/register`, which re-enters the same middleware, unless `req.session.registration` exists, so the retarget the Requirements literally asked for is an INFINITE LOOP on its own. The sibling handler that ALREADY redirects there (accounts/edit.js) spells out the state to seed; a bullet naming only the `Location` header still implies it. Put a loop case in the throwaway suite: request the TARGET path itself and assert `next()`.
